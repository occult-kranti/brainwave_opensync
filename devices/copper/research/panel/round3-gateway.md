## Concrete parser failure, repair and retest

The original command described an inventory rather than a comprehensive validator, but invisible omissions undermined its metadata-check coverage.

Root authorized a bounded repair to both canonical skill and app copy. The revised parser:

- rejects duplicate JSON keys and preset IDs, missing/non-string fields, invalid numbers, unknown constructions and inconsistent differences;
- rejects nonstandard non-finite JSON constants and overflowing standard float tokens, including unused nested metadata;
- explicitly classifies supported carrier-pair, pulse-train and noise forms;
- emits record/arithmetic/non-carrier coverage counts, with pulse/noise labelled `not-carrier-pair-arithmetic`;
- preserves committed-tree-only scope, symlink non-following and exclusive output creation; errors return nonzero without invented success JSON.

The root critic caught an additional edge in the first repair: JSON `1e400` is handled by `parse_float`, not `parse_constant`. A finite-float callback and an unused nested-overflow fixture were added before admission. The final parser is **not an exhaustive validator of arbitrary stimulus schemas**, and arithmetic/classification still says nothing about delivered waveforms or outcomes.
