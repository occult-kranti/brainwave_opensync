## Recommended skill additions

1. **Dedicated work packets.** Assign each worker a bounded question, permitted files, precise output, source starting points, independent discriminator and stop rule. Give reviewers the statement and frozen inputs; disclose whether they inherited producer discussion. Separate workers are useful for disjoint source and operator work, not evidence of independence by themselves. Return concise findings plus artifact paths. [S3, S4, S5]
2. **Navigate a scoped knowledge base.** Keep the main skill short. Link one level down to a task index, source ledger, exact contract, active objections and executable receipts. Load only the section needed for the current claim. Check repository instructions from the actual working directory; verify those instructions loaded instead of assuming all nested guidance applies. [S1, S2, S6]
3. **Make graph semantics explicit.** Edges must name `documents`, `motivates`, `tests`, `supports` or `contradicts`, point to a read source section or executed artifact, and expose scope/limitations. Do not promote a search hit, title match, similar equation or graph path into a proof. This is a project evidence rule, not a measured result from the provider guidance.
4. **Fresh-context validation.** Supply a fresh reviewer the exact statement, domain, code revision, input contract and acceptance criteria. Ask them to reconstruct one claim without the producer’s narrative and select a withheld counterexample. Record inherited context honestly. Context isolation reduces shared narrative exposure; shared model and sources still allow correlated mistakes. [S3, S5]
5. **Adaptive exchange.** Freeze each round only after the preceding reports are available. Record incoming artifact hashes, the objection received, the concrete change it caused, executed checks, accepted narrow result, rejected interpretation and next question. A later round may close an objection rather than enlarge scope. This operationalizes the current resonance contract; it is not a universal three-round recipe.
6. **Repair the workflow from observed failures.** Add a small executable check only after a recurring error or an uncovered acceptance gate; test the amended skill against the exact failure and one normal case. Keep reusable procedure in the skill and run-specific evidence in the project. Maintainer examples are patterns to test locally, with licenses checked before reuse. [S2, S6, S7]
